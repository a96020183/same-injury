# Same Injury — recorded demo

Open `index.html` directly, or serve this folder with any static web server. No install, account, key, Docker service or internet connection is required. JavaScript must be enabled.

1. Choose **Demo company**, then **Find the systems**. Inspect Discovery’s table classifications, field maps and recorded unified model.
2. Select **Continue recorded run**. Open a case in either direction to read its searches, agent exchanges and query receipts.
3. Open the featured case to inspect a SYNTHETIC scanned form. Each query button opens its SQL, identity, result hash and recorded rows.
4. Choose **Unseen company**, then open the featured case. The SYNTHETIC L4 pair shows the Evaluator and code Verifier disagreeing over what another address proves.
5. Open **Trace** to filter key decisions or every event by agent. A case can open its own trace. Dialogs support Escape, keyboard navigation and focus return.

The opening three-record example always comes from **Demo company** and is labelled accordingly. **Open Demo company case** selects that recording explicitly. The workflow selector controls Discovery, matching results and Trace; the opening illustration stays the same.

The default results are **before identity approval**. The later snapshot shows automatic operator approvals already performed in the original recording. Those approvals demonstrated the workflow; they were not human reviews. Your clicks never approve an identity or change a recorded outcome.

## What is replayed

- Original trace events and case snapshots from demo run `20261027-023325-7fc3` and unseen-company run `20261027-025156-9960`.
- Table classifications and field maps reproduced through the repository’s no-network SAMPLE_MODE. Pre-approval items and query-bearing event sequences were checked for exact equality with the original recordings.
- Receipt metadata regenerated offline, with query results checked against the SQL cassettes. It is **not an original live receipt file**. Each receipt explicitly identifies the export backend. All exported receipt results matched a bundled recording.
- Up to 24 rows per receipt. Full-result row counts and hashes remain visible; omissions are labelled. Some post-review operator receipts were not exported and are shown as plain “not included” labels, without a button.
- SYNTHETIC forms for invented plants only. No employee name is shown.

There are no API calls, live model runs, new data generation, compilation, access grants, identity approval/rejection, new scoring, or live counsel export. The downloadable JSON is the supplied replay, not a newly generated report. Both sealed-exam runs and the baselines are presented separately; schema-discovery scores are not matching accuracy.

## Reading the results

All negative conclusions belong to invented plants explicitly marked **SYNTHETIC**. Other records are de-identified composites with neutral outcomes only. De-identification does not guarantee anonymity; public case patterns can remain recognisable. The repository README describes these limits.

“Not found” means not found after the recorded searches in the listed sample. It never establishes failure to report. A State Plan maintains its own records, outside the federal file searched here. A label saying “for counsel review” does not establish privilege; counsel decides how the output is handled.

Zetaris supplies federated evidence and access control in the original product. Nightshift routes the original model calls. The Meterless World Model holds shared state and identity proposals. This site implements none of those services. The recorded runs used isolated model scopes; the original README explains how a live run’s default user scope differs.
