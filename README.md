*Build period and history.* Everything here was written from 2026-10-22 00:00 UTC. The git history was rebuilt to remove identifying data (on 2026-10-24, twice on 2026-10-26 when QA found that earlier versions of the negative cases could be traced, three times on 2026-10-27: after synthetic and negative cases moved from real plants to invented ones, after the output gate replaced real plants' published log fields with codes, and after every synthetic record was regenerated from a seed instead of being edited from a real case): it starts with one commit of 2026-10-27, so it cannot show when code was written. When a worker loses a fingertip, the injury is written down three times: in the plant's own log, in the phone report OSHA takes, and in the inspection record DOL opens afterwards. The plant log and OSHA's report share no key: the only thread between them is the place (house number and ZIP) and the week. OSHA's report and DOL's inspection are linked: the report's referral number leads to the inspection (and, once an inspection is open, the report's Inspection field is DOL's inspection number in another format).

**Same Injury** helps a multi-site company's injury-records lead, working under counsel, match every serious injury in its site logs with OSHA's severe-injury reports, in both directions, before the yearly summary (OSHA 300A) is certified. Agents find which of the company's systems hold injury records, map their fields, and decide which records describe the same injury. Every conclusion carries the queries that produced it. The output is an audit list prepared for counsel review (a label does not create privilege; counsel decides how it is handled): where the agents searched and what they found. It never says anyone failed to report.

> Track 1 — Solving Fragmented Intelligence. Zetaris holds all evidence and enforces who sees what; the Meterless World Model is the agents' shared state; every model call goes through Meterless Nightshift to NVIDIA Nemotron (three lanes, including Nemotron VL for paper forms).

## Run it (5 minutes, no keys)

Requirements: Node.js ≥ 22.13 (uses the built-in `node:sqlite`), npm.

```bash
npm ci
npm start         # the app: http://127.0.0.1:8740 — press "Find the systems" (replay speed: instant / normal / slow)
npm run demo      # the same loop in the terminal, ~1 s; both human gates taken by an operator flag
npm test          # app and World Model tests, no network
python -I scripts/verify_exam.py   # sealed exam: re-check every hash and re-score both runs from the repo
npm run vl        # Nemotron VL on two extra scanned 301 forms (recorded answers)
```

`SAMPLE_MODE=true` is the default. Every SQL statement is answered by the response the local Zetaris gave in the recorded live run (`sample/seed1003/zetaris_cassette.jsonl`); a statement never recorded is answered by a bundled emulator over the same CSVs with the same masks. Every model call is answered by the recorded Nightshift reply (`sample/seed1003/model_cassette.jsonl`); with no recording and no token an agent's deterministic fallback answers and the trace labels it `offline-stub` (the recorded run needs none). Each receipt says which backend answered and under which Zetaris identity (`agent-role` or `admin`). The emulator has no users or roles: when it answers a `GRANT` or `ASSIGN` it says `emulator: not enforced`, and only live Zetaris refuses what the agent role may not do ([docs/zetaris_vs_emulator.md](docs/zetaris_vs_emulator.md)).

If Zetaris or Nightshift is down in live mode the run does not fail: SQL falls back to the recording or the emulator (the receipt says so), and a lane whose model call fails is escalated to a person instead of guessed.

## What the agents do

**Who is asking.** The agents query Zetaris as `agent@l1.local`, a non-admin role. Zetaris assigns it seven sources, grants table by table, and masks employer, establishment and plant names (and street names, keeping house numbers) with native column policies. The reviewer's administrator key is used only after a person approves: to compile the unified model and to show the reviewer the names. Screenshots of the same SQL in the Zetaris UI under both identities: `docs/screens/`.

**Layer 1 — which systems hold injury records.** Discovery reads the catalog as the agent role (`SHOW DATASOURCES`, `SHOW LIGHTNING DATABASES`, `SHOW DATASOURCE TABLES`, `SHOW LIGHTNING TABLES`, `DESCRIBE DATASOURCE TABLE`), skips database system tables when a source lists them, reads three sample rows per table and asks Nemotron to classify each table (injury log, site list, yearly summary, OSHA reports, DOL, letters, or *not injury records*: maintenance, training, HR, near-miss, first aid) and map its fields. The Verifier (code) tests every map with SQL — does the date format parse every row, does every case have a site — and, after compilation, whether every site's case count equals its 300A total. A failed check goes back to the Planner (model), which revises the map. A site whose case count differs from its 300A total goes on the person's *Before you certify* list. Then a Unified Semantic Layer is drafted with no name columns at all; **`COMPILE USL` waits for an administrator to approve**, after which the app compiles and activates it with the administrator key and grants the two unified tables to the agent role.

**Paper forms — Nemotron VL.** One plant system keeps its log on paper OSHA 301 forms; its table has no body-part column. For every amputation log line that has a scanned form (whatever system it came from), the Reader sends the form, with the employee name blacked out, to Nightshift's vision lane, reads case number, date, time, job, side and body part, checks them against the typed log, and writes the reading into the World Model. The Linker and the Evaluator compare OSHA's report with the side and finger the form says. If the vision lane fails after its retries, the lane continues on the typed text and the trace says so.

**Layer 2 — which records are the same injury, both directions.** One lane per log amputation and per OSHA severe-injury report (amputation or in-patient hospitalization) near our plants. First, one federated query — the unified log (four engines behind the USL) × OSHA's file × DOL's related-activity and inspection tables — maps every same-address, same-week pair (`docs/explain_candidate_map.txt` shows the plan Zetaris builds for it). ### What it decides

| Plant log → OSHA | OSHA → plant log |
|---|---|
| Reported — OSHA has it | In the log |
| Reported — written differently (what differs is listed) | In the log, written differently |
| May not need a report (a 1904.39(b) exclusion: (b)(3) road, (b)(6) >24 h, (b)(11) avulsion — counsel to confirm) | Not found in this company's log sample |
| No matching report found in this sample (composite company) (every place searched, with query IDs) | |
| State Plan state — its own records, outside OSHA's federal file (the federal file is searched like any other; State Plans set their own reporting rules, 29 CFR 1904.37(b)(2), and may keep the report in their own records, which this run cannot read; not an exemption) | |

Every item stays *waiting for your review* until the reviewer accepts the identity it depends on; a same-address or same-ZIP, same-week amputation that the Evaluator calls different without a receipt showing another site or injury is sent back by the Verifier and, if nothing settles it, goes to a person, never to "not found". A per-plant table, *Before you certify the 300A*, counts what to add, what to review and what goes to counsel; a real plant appears there only with neutral results, and anything else at a real plant is one count in its last row (the output gate). Below it, *Next steps* says who does what and by when, with the rule behind each deadline: add a missing case within 7 calendar days (29 CFR 1904.29(b)(3)); where the two records disagree, find out which is right and update the log only if the log is wrong (1904.33(b)(1)); when OSHA's phone report says less than the log (no amputation flag), counsel decides whether to update OSHA; send log amputations with no OSHA report to counsel (an amputation is reported within 24 hours, to OSHA or the State Plan, 1904.39(a)(2), 1904.37(b)(2)); one injury seen from both directions counts once; then a company executive certifies the 300A, it is posted Feb 1 – Apr 30 and submitted by March 2 where required (1904.32, 1904.41). A checklist, not legal advice.

**Who decides what.** Every judgement is a model call (Nemotron through Nightshift). Code fetches data, checks that a judgement rests on receipts (the Verifier), and re-runs citations (the Skeptic); it never replaces a judgement.

| Agent | Decides | Model or code | Why |
|---|---|---|---|
| Discovery | which sources and tables hold injury records; the field map | model (`fast`) | names, columns and date formats differ in every company |
| Planner | the order of the searches; the next research step after an objection; when to escalate to a person | model (`fast`) | which step can produce the missing receipt depends on what is missing |
| Reader | what a scanned 301 form says | model (`vision`) | handwriting on paper |
| Linker | for each candidate: link, send to the Evaluator, or drop | model (`fast`) | the call is a judgement |
| Evaluator | same injury, different, not enough, or escalate, citing receipts; the six competing explanations | model (`deep`) | conflicting records need reading, not matching |
| Research | both narratives side by side (model `fast`); DOL inspections, our plants at a ZIP, other OSHA reports, reply letters (SQL) | model + code | reading is a model task; lookups are data access |
| Verifier | whether a decision rests on receipts: a link needs the same house number, ZIP, week and injury; "same" at another address needs a receipt that places the report; "different" for a same-ZIP, same-week amputation needs a receipt that shows another site or injury; "another site" can only be ruled out by a placing receipt | code | a check must not be the model checking itself; it objects, it never decides |
| Skeptic | whether every cited query still returns the same rows | code | same reason |
| World Model, Wording guard, Final | identities wait for a person; neutral wording; the list re-read from the World Model | code | bookkeeping and policy, not judgement |

The trace panel opens on the key decisions (rejections, re-plans, approvals, escalations, the Skeptic) with counts computed from the trace; *Every event* shows the rest.

**Behind every conclusion.** When two records do not line up, the Evaluator weighs six explanations — same injury written differently, a different injury, a nearby report about another site, reported to the State Plan rather than OSHA (only a State Plan record can support it; without one it stays open), a 1904.39(b) exclusion, no report in OSHA's file — and marks each supported, ruled out or still open, citing the receipts (`app/agents/hypotheses.ts`; shown in the trace, the lane drawer and the counsel export). After matching, a **Skeptic** agent re-runs every query a conclusion cites, as the same Zetaris identity, and compares an order-free hash of the rows; a citation that does not reproduce sends its lane back to the Evaluator (`app/agents/skeptic.ts`). The **Verifier** checks the explanations too: "another site" can only be ruled out by a receipt that places the report; otherwise it stays open. In SAMPLE_MODE the re-runs replay the same recording, and the screen says so.

## Why Zetaris and not a copy of the data

The bundled SQLite emulator answers the same SQL, so the question is fair. `scripts/zetaris_parity.ts` runs the same statements on both ([docs/zetaris_vs_emulator.md](docs/zetaris_vs_emulator.md)): on live Zetaris the agents' key reads masked names while the reviewer's key reads the codes, and the agent role is refused when it tries to GRANT itself access, COMPILE the unified model, or read another company's sources. The emulator does none of that, and it only works because every table was first exported to one place, which is the step a plant's EHS data cannot take. Live, the candidate map is one federated query across four engines, OSHA's file and DOL, with filters pushed down to each engine.

## Zetaris notes from building this (2.4.3.1, local Docker)

- `lower(col) LIKE '%x%'` alone on a JDBC source returned wrong results (0 rows; `count(*)` ignored the filter). `col rlike '(?i)x'` is correct.
- `ACTIVATE USL TABLE` checks nullability: a `NOT NULL` column needs `COALESCE(x, '')`.
- A fresh install has no `lightning.metastore` namespace; create it first.
- A non-admin role needs the USL namespace assigned, `GRANT SELECT ON USL TABLE`, and an activated table. `SHOW DATASOURCE TABLES … WITH STATISTICS` and `EXPLAIN` are admin-only.
- Column policies have no SQL command; `scripts/setup_governance.py` writes them through the API the Zetaris UI uses. A `masked` policy replaces every regex match with `*`.
- S3 file stores are reached virtual-host style: bucket name ≥ 3 characters and a DNS alias `<bucket>.<host>`. SeaweedFS (S3 API) stands in for MinIO.
- DOL's API key works only as a URL parameter, so `UPSERT AUTH` cannot hold it; the app reads a DOL snapshot so a run is repeatable.
- OSHA's report and DOL's inspection do share a key. The public file's `Inspection` field, filled once an inspection is open, is DOL's `activity_nr` in another format ("34" + its last six digits + a check digit; this matched 6 of 6 cases we tried). The agents do not use it: in the samples both fields are replaced by independent codes (*INSP-…*, *DOL-…*), so the format rule cannot be applied there, and they follow OSHA's referral number → `related_activity` → `inspection`, which exists from the referral on, before any inspection is opened. The step with no shared key is the plant log → OSHA's report.

## Limits

- One demo company, re-sharded on purpose; the fragmentation across agencies is real.
- Shifted dates and swapped states do not stop someone with the public files, and the real plants' case counts and published reports can point to the source companies (numbers in *Data* and *Secrets and names*). That is why every SYNTHETIC record and every negative conclusion sits in an invented plant; the conclusions in real plants repeat what OSHA already published.
- "Not found" means not found in OSHA's federal file after the listed searches; it is not a finding about reporting. In a State Plan state the lane says only that: the State Plan keeps its own records, which this run does not read.
- The step that groups the public ITA companies and orders the pool is kept outside the repository (`scripts/scan_identity.py` fails if a tracked script builds or orders it), but that does not hide the source companies: their plants' case counts and their published reports point to them (see *Data*). The sealed exam's tables (Layer 1 only: no conclusion about any plant) keep the published 300A rows and log fields (case numbers, job titles), because changing them would break the exam's hashes; their companies are recognisable the same way.
- An OSHA report at another house number in one of our ZIPs is "not ours" unless a log amputation sits in the same week (then the Evaluator judges it). OSHA's employer name is masked for the agents, so a report filed under our own company at an address missing from our plant list can be missed; the reviewer, who sees names, is the check.
- The demo company and the unseen company are composites of public records; real plant systems would have more tables and messier names.
- The vision lane was unstable on 2026-10-23 (most image requests failed; all 4 succeeded on 2026-10-24); it retries, falls back to the typed text, and the demo replays recorded answers.
- The scanned forms are synthetic renderings of the public case text; the typed group-D table is the generator's transcription.
